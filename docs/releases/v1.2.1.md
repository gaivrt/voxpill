# VoxPill 1.2.1 — macOS experience alignment

macOS Apple Silicon and Intel now use the same animation and raster renderer as
Windows: a 36 px four-bar orb, 260 ms entrance, spring expansion up to 440 px,
45 ms character reveal, accelerated recognition bars, and a 340 ms shrink/fade
exit. The Mac adapter handles Retina scale, input-window monitor placement,
native non-activation and click-through presentation. Both themes are recorded
as native-window animations during package validation.

Mac settings now record key presses/chords directly, with re-record, default,
cancel, temporary event suppression and live application of the saved binding.
Mac labels use Control/Option/Command. The menu-bar icon follows system theme;
an optional per-user start-at-login toggle is included.

Before insertion, Mac restores the original input window and focused control
through Accessibility, failing closed for invalid targets. Clipboard failure
falls back to Unicode typing. Existing offline ASR, audio guards, clipboard
options, Enter option, single-instance lock and cleanup remain in place.

Verification includes a 276-frame reference generated from the published Windows
1.1.1 animation, unit tests for capture/focus/login behavior, native ARM64/Intel
builds, rendered animations and package smoke tests. Actual third-party input
applications, physical microphone/keyboard, permission approval and multi-monitor
behavior still require hands-on Mac acceptance. CI success alone is not that acceptance.

Install the correct Mac archive into Applications. Grant Microphone and
Accessibility/Input Monitoring permissions as prompted. The app is still
unsigned/not notarized because no Apple Developer ID is configured. Linux
remains at its existing X11 subtitle feature level; this update aligns Mac.
